# LinuxUnity Project Context

## Project scope
- This repository is a single deployable Next.js 16 + React 19 + Payload CMS 3 application.
- PostgreSQL is the authoritative CMS database; Redis stores cache/rate-limit state; Payload media currently uses the persistent local `payload_media` volume while S3/CDN is disabled.
- Vietnamese is the default locale; English routes live under `/en`.
- Payload is the source of truth whenever a query succeeds. Local `content/` and `data/` are fallback sources only when Payload is unavailable or a query fails. Never merge fallback entities into a successful empty CMS result.

## Read before changing code
- Start with `README.md`, `docs/REPOSITORY_STRUCTURE.md`, and the documentation relevant to the requested feature.
- Inspect the affected route, service, collection, migration, and regression tests before editing.
- Prefer small, targeted changes. Do not perform bulk directory moves or unrelated cleanup.

## Git workflow
- `main` is production. Never make feature changes directly on `main`.
- Create a branch from the current `origin/main`: `feature/*`, `bugfix/*`, `hotfix/*`, or `chore/*`.
- Do not commit, push, open a PR, merge, deploy, or rewrite history unless the user explicitly requests it.
- Do not discard or overwrite uncommitted user changes.

## Required verification
Use Node.js 24 and install from the lockfile with `npm ci`.

Before declaring a code change complete, run:
1. `npm run lint`
2. `npm test`
3. `npm run build`

For deployment-related changes, also validate the Docker image when Docker is available:
`docker build --file ./Dockerfile --tag cloud-devops-blog-app:ci .`

If a gate cannot run, report the exact blocker and do not claim it passed. Add or update a focused regression test for bug fixes and behavior changes.

## Production and data safety
- Never commit `.env`, credentials, tokens, database dumps, uploads, backups, or runtime data.
- Never invent production secrets or replace an existing production `.env` from `.env.example`.
- Production images are built only by GitHub Actions, tagged with immutable Git SHAs, and stored in ECR.
- The VPS must pull the exact image and run Compose with `--no-build`; never build production source on the VPS.
- Run an off-host backup before Payload/Postgres migrations. ECR is not a database or media backup.
- Treat full data rollback as destructive; require explicit user confirmation and an accepted recovery point.
- Preserve existing migration history; create a new migration rather than editing an already-applied migration unless explicitly required.

## Important paths
- `src/app/`: Next.js routes and presentation
- `src/collections/`, `src/blocks/`: Payload schema and rich-content blocks
- `src/lib/`: server integrations, auth, cache, content access, and utilities
- `src/migrations/`: Payload/Postgres migrations
- `content/`, `data/`: local fallback content/runtime stores
- `tests/`: Node regression tests
- `scripts/`: import, translation, backup, deploy, and rollback tools
- `.github/workflows/deploy-production.yml`: production CI/CD
- `docs/CICD_DEPLOYMENT.md`: deployment, backup, and rollback runbook

## Working style
- Explain assumptions and risks concisely in Vietnamese unless the user requests another language.
- Read existing implementations and tests instead of guessing conventions.
- Keep generated files and dependency/build output out of Git.
- After editing, review `git diff`, run the relevant focused test first, then run all required gates.
