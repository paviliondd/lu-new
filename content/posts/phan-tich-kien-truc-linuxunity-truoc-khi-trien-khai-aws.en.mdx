## 2. System requirements

### Functional requirements

- Publish and display articles.
- Manage content through Payload CMS.
- Use Vietnamese as the default language and serve English under `/en`.
- Manage categories, tags, series, and media.
- Support search, comments, and view counts.
- Authenticate users through GitHub or Google.
- Render SEO metadata, sitemaps, and RSS feeds.

- Fall back to local content when Payload is unavailable or a query fails.
- Preserve production data across container restarts.
- Identify every application image by an exact version.

## 4. Core components

| Component | Technology | Responsibility |
|---|---|---|
| Web application | Next.js App Router, React, TypeScript | Renders the interface, routes, APIs, and SEO output |
| CMS | Payload CMS | Manages articles, media, users, and comments |
| Database | PostgreSQL | Stores Payload's primary data |
| Cache/runtime support | Redis | Supports caching and runtime data |
| Reverse proxy | Nginx | Accepts requests and proxies them to the application |
| Container runtime | Docker Compose | Starts and connects the current services |
| Media storage | Docker volume | Stores files uploaded through Payload |
| Fallback storage | Local content and JSON data | Used when Payload is unavailable or a query fails |

## 13. Architectural decisions to preserve

- Payload CMS remains authoritative whenever it is reachable.
- Local data is a fallback and must not be merged into a successful CMS query.
- Vietnamese remains the default locale, with English served under `/en`.
- Next.js, Payload CMS, PostgreSQL, and Redis remain the core stack.
- CMS, SEO, media, comments, and OAuth capabilities must remain intact.
