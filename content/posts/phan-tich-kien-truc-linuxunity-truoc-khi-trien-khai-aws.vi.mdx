## 2. Yêu cầu của hệ thống

### Yêu cầu chức năng

- Xuất bản và hiển thị bài viết.
- Quản lý nội dung bằng Payload CMS.
- Hỗ trợ tiếng Việt mặc định và tiếng Anh qua `/en`.
- Quản lý categories, tags, series và media.
- Hỗ trợ tìm kiếm, bình luận và lượt xem.
- Đăng nhập bằng GitHub hoặc Google.
- Render SEO metadata, sitemap và RSS feed.

<!-- TODO: Bổ sung hoặc điều chỉnh theo chức năng thực tế muốn giới thiệu trong bài. -->

### Yêu cầu phi chức năng

- Giao diện responsive và hỗ trợ dark/light theme.
- Nội dung vẫn có fallback khi Payload không khả dụng hoặc truy vấn thất bại.
- Dữ liệu production phải tồn tại qua các lần restart container.
- Application image phải có thể xác định chính xác theo phiên bản.
- Hệ thống phải hỗ trợ backup và khôi phục dữ liệu.

## 4. Các thành phần chính

| Thành phần | Công nghệ | Vai trò |
|---|---|---|
| Web application | Next.js App Router, React, TypeScript | Render giao diện, route, API và SEO |
| CMS | Payload CMS | Quản lý bài viết, media, user và comment |
| Database | PostgreSQL | Lưu dữ liệu chính của Payload |
| Cache/runtime support | Redis | Hỗ trợ cache và dữ liệu runtime |
| Reverse proxy | Nginx | Tiếp nhận và chuyển tiếp request đến application |
| Container runtime | Docker Compose | Khởi chạy và kết nối các service |
| Media storage | Docker volume | Lưu file được upload qua Payload |
| Fallback storage | Local content và JSON data | Dùng khi Payload không khả dụng hoặc query thất bại |

## 13. Các quyết định kiến trúc cần được bảo toàn

- Payload CMS là nguồn dữ liệu có thẩm quyền khi có thể truy cập.
- Local data chỉ là fallback, không được merge vào một CMS query thành công.
- Tiếng Việt là locale mặc định; tiếng Anh được phục vụ qua `/en`.
- Next.js, Payload CMS, PostgreSQL và Redis tiếp tục là stack cốt lõi.
- Các tính năng CMS, SEO, media, comment và OAuth phải được giữ nguyên.
